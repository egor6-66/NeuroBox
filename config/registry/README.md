> [!IMPORTANT]
> **`npm login` не работает, и это следствие требования «анонимно писать нельзя».**
> Самостоятельная регистрация в реестре закрыта (`max_users: -1`), а npm ходит за токеном в ту
> же ручку, что и за регистрацией. Публикация — по токену из `.npmrc`.

Новый токен или ещё одна учётка:

```bash
sh /opt/neurobox/config/registry/issue-token.sh <имя> <пароль>
```

Скрипт поднимает одноразовый контейнер на том же томе: боевой реестр не трогается, его конфиг
остаётся тем, что лежит в репозитории.

## 📝 `.npmrc`

Для публикации:

```
@web-core:registry=https://150.251.145.87:9873/
//150.251.145.87:9873/:_authToken=ZmU3MWRkNzU1NjE2NDdjNDQ3ZGVjNzNhNmFmZWY2ZTI6MmY2NTk5MzJkODM0N2Y1NWVhZDczODk5Zjc2NzQwMjk4MGQ1YzRkZDEyZjJkY2I2YmJkMTdlMGJhNw==
```

Для потребителя — токен не нужен:

```
registry=https://150.251.145.87:9873/
```

Эта строка отправляет в реестр **все** пакеты, чтобы публичные зависимости шли через его кэш.
Нужно тянуть публичное напрямую с npmjs — оставьте только `@web-core:registry=…`.

## ⚖️ Что разрешено

- **Читать — всем, без токена.** Осознанный размен: пакеты не секретные, а демо-проекту так не
  нужен токен, чтобы просто собраться.
- **Публиковать — только по учётке.**
- **Снимать и перезаписывать версию — можно.** На обкатке одну версию публикуют многократно, и
  запрет остановил бы работу на втором шаге. Для боевого реестра это выключают.
- **Публичный npmjs проксируется с кэшем.** Без этого чужой проект, ставящий наши пакеты, не
  собрал бы их зависимости.
- **Скоуп `@web-core/*` НЕ проксируется.** Его в публичном npmjs нет, и поход туда дал бы чужой
  404 вместо нашего честного «нет такой версии».

## 💾 Данные

| Что | Где |
|---|---|
| Пакеты и учётки | том `neurobox_registry-data` → `/var/lib/docker/volumes/neurobox_registry-data/_data` |
| Конфиг | `config/registry/config.yaml` этого репозитория, примонтирован только на чтение |

Правки конфига — только через репозиторий. Реестр читает его **при старте**, поэтому после
правки нужен явный перезапуск: `docker restart neurobox-registry-1`.

Резервная копия:

```bash
docker run --rm -v neurobox_registry-data:/d -v /root:/out alpine \
  tar czf /out/registry-backup.tgz -C /d .
```

Начать с чистого листа:

```bash
docker compose -f /opt/neurobox/compose.yaml rm -sf registry
docker volume rm neurobox_registry-data
docker compose -f /opt/neurobox/compose.yaml up -d registry
sh /opt/neurobox/config/registry/issue-token.sh web-core <пароль>
```

## ⚠️ Ошибка, найденная приёмкой

В конфиге был `url_prefix: ${VERDACCIO_PUBLIC_URL}`. Реестр **не подставляет переменные в своём
конфиге**, и имя переменной уехало прямо в ссылки на тела пакетов:

```
404  'zod@https://150.251.145.87:9873/$%7BVERDACCIO_PUBLIC_URL%7D/zod/-/zod-4.6.5.tgz'
```

Публикация при этом проходила — падала только установка. Починено: адрес берётся из штатной
переменной окружения `VERDACCIO_PUBLIC_URL` и заголовков источника, которые шлёт вход.

Причина, по которой это стоит помнить: своего `url_prefix` в конфиге быть не должно.
