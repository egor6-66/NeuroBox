<h2 id="главное">🏠 Главное</h2>

📁 Файловый слой конфигурации — **первый слой** из трёх (разбор слоёв — в
[корневом README](../README.md#слои)). Это твои личные стандарты: лежат в гите, ездят с тобой по
машинам, правятся руками и коммитятся как код.

✋ Не потроха сервиса, а данные для него. Поэтому отдельная папка: её содержимое человек открывает
и меняет постоянно, а [`neurobox/`](../neurobox/README.md) — почти никогда.

<h2 id="анатомия">🧩 Анатомия</h2>

| Часть        | Что держит                                                      |
| ------------ | ---------------------------------------------------------------- |
| `mcp.json`   | серверы-семена: адреса, заголовки, команды `stdio`-серверов      |
| `seeds/`     | знание-семена: маркдаун с шапкой                                 |
| `passports/` | чем агент думает: провайдер, модель, лимиты, семплинг            |
| `recipes/`   | рецепты: списки имён семян                                       |

🪪 **Пространство имён у семян одно, содержимое двух видов.** Рецепт перечисляет имена и не знает
природы семени — поднять сервер или подложить текст в инструкцию решает сервис.

📋 **Серверы держатся в исходном формате намеренно.** `mcp.json` — ровно та же форма, что у любого
другого инструмента с поддержкой MCP, чтобы запись переносилась копированием. Свой формат стоил бы
совместимости и не дал бы взамен ничего.

🧭 **Паспорт в рецепте не называется.** Человек выбирает отдельно, кем работать, и отдельно, над
чем: один и тот же рецепт осмысленно запускать и на облачной модели, и на локальной.

<h3 id="требования">📐 Требования семени</h3>

Семя вправе заявить, чего оно требует от модели — **минимум** и **рекомендуемое**. Поле
необязательное: перечень моделей открытый, и автор семени не может знать, на чём его запустят.

| Требование           | С чем сверяется                                             |
| -------------------- | ------------------------------------------------------------ |
| контекст             | окно модели из паспорта                                      |
| вызов инструментов   | умеет ли модель звать тулзы — без этого семя-сервер бесполезно |
| строгий вывод        | нужен ли семени структурированный ответ                       |

📏 **Часть требования измеряется, а не заявляется.** Сервер опрашивается при подключении, поэтому
вес его перечня тулзов и инструкции считает сервис. Руками заявляется только то, что не
измеряется.

🚦 **Исходов три, и ни один не блокирует.** Подходит — тихо. Слабовато — предупреждение, но запуск
разрешён: решать человеку. Не с чем сравнить (паспорт не заявил окно, семя не заявило требований) —
честное молчание, а не претензия. Сервис, отказывающийся работать из-за незнакомой модели, был бы
хуже, чем сервис без проверки вовсе.

💡 Всё, что не сверяется машинно («нужна умная модель»), живёт отдельным полем-подсказкой и
называется подсказкой. Смешивать проверяемое с пожеланием нельзя — тогда обесценивается и то,
и другое.

<h2 id="использование">🚀 Использование</h2>

Слой перечитывается на КАЖДЫЙ запрос: правка файла видна сразу, без рестарта контейнера. Папка
примонтирована в образ только на чтение. Элемент отсюда перекрывается одноимённым из базы — и
наоборот, элемент из базы можно перенести сюда осознанным экспортом. 🚫 Обратной автоматической записи нет:
сервис в эту папку не пишет никогда, иначе гит начал бы шуметь сам по себе.

<h2 id="ио">🔌 ИО</h2>

🔐 **Секреты сюда не кладутся.** Токены подставляются из окружения через `${VAR}`:

```json
{
  "mcpServers": {
    "windshift": {
      "type": "http",
      "url": "http://10.8.1.3:8095/mcp",
      "headers": { "Authorization": "Bearer ${WINDSHIFT_TOKEN}" }
    }
  }
}
```

Нет переменной — сервер не поднимается. Это заметная поломка, а не тихая: сервер, молча
пропущенный из-за отсутствия токена, выглядел бы как «агент почему-то не умеет».

<h3 id="адреса">🌐 Адреса серверов из контейнера</h3>

🏠 **Сервер на своей машине — не `127.0.0.1`.** Внутри контейнера это он сам. Хост доступен как
`host.docker.internal` — на Docker Desktop имя есть само по себе, на голом Linux его создаёт
`extra_hosts` в `compose.yaml`.

🛡️ **Сервер вправе отказать чужому имени.** MCP-серверам рекомендовано проверять заголовок `Host`
— это защита от атаки через подмену DNS, и работает она в том числе против нас: сервер, знающий
только `localhost`, ответит `403` на обращение по `host.docker.internal`. Отказ придёт с именем
`server-silent` и настоящей причиной в тексте. Лечится на стороне СЕРВЕРА (разрешить имя), а не
обходом здесь.
