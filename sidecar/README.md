<h2 id="главное">🏠 Главное</h2>

📦 Контейнер для MCP-серверов, которые говорят по `stdio` и приносят с собой окружение: node,
браузер, файлы чужих репозиториев. Здесь они поднимаются и оборачиваются в http, чтобы наружу
торчал один транспорт.

🎯 Смысл границы: **зоопарк заперт здесь**. [`neurobox/`](../neurobox/README.md) остаётся тонким и
одинаковым у всех, «поставить ещё один сервер» это правка одной папки, и упавший сервер не роняет
сессии. Это единственное место в репозитории, которое человек пересобирает под себя.

<h2 id="анатомия">🧩 Анатомия</h2>

| Часть        | Назначение                                                            |
| ------------ | ---------------------------------------------------------------------- |
| `Dockerfile` | окружение: node, git, Claude Code; дальше браузер для тех, кому нужен   |

Контейнер не сервис — он поднимается по требованию под конкретную команду, поэтому в
`compose.yaml` объявлен профилем и обычным `docker compose up` не поднимается. Контейнер,
висящий без дела, врал бы про состав работающей системы.

<h3 id="вход">🔑 Вход в Claude Code</h3>

Авторизация лежит на именованном томе, а не внутри образа: иначе логин пропадал бы при каждой
пересборке. Каталог создаётся в образе с нужным владельцем ЗАРАНЕЕ — свежий том докер заполняет
содержимым и владельцем того, что лежало в образе на этом месте, а без каталога том достаётся
`root`, и CLI под пользователем `node` в него не пишет.

Вход — один раз, руками, с терминалом:

```bash
docker compose run --rm -it claude claude auth login --claudeai
```

Ссылку из терминала открываешь в браузере на хосте. Проверить потом:

```bash
docker compose run --rm claude claude auth status
```

<h3 id="развёртка-в-cli">🧩 Как сюда ложится развёртка</h3>

CLI принимает ровно то, что развёртка отдаёт: `--system-prompt` для инструкции и `--mcp-config`
для серверов. Плюс `--strict-mcp-config` — агент видит ТОЛЬКО серверы рецепта и ничего сверх, что
и делает рецепт настоящей границей, а не пожеланием.

<h2 id="использование">🚀 Использование</h2>

Серверы объявляются там же, где все остальные — в [`config/`](../config/README.md), обычной
`stdio`-записью с командой и аргументами. Сайдкар читает те же записи; для рантайма разницы между
таким сервером и внешним http-адресом нет.

➕ **Добавить сервер или инструмент** — дописать запись в конфиг и, если он тянет новое
окружение, дописать `Dockerfile` здесь. Всё внешнее и необязательное селится сюда: зона для
этого и заведена.

🚪 **Запасной выход.** Кому этой границы мало — собирает свой образ поверх базового. Это осознанный
выход, а не обход канона: он берёт на себя и вес образа, и его пересборку.

<h2 id="ио">🔌 ИО</h2>

📥 На входе — объявления `stdio`-серверов из конфига.
📤 На выходе — те же серверы по http, неотличимые для рантайма от внешних.

🚦 Сервер, который не поднялся, отдаётся именованным отказом наверх — молчаливого пропуска нет.
