<h2 id="главное">🏠 Главное</h2>

📦 Чужое тяжёлое окружение и живущий в нём **A2A-агент**. Здесь стоят node, Claude Code и всё,
что тянут за собой `stdio`-серверы, — а наружу торчит один общий протокол.

🎭 Снаружи агент, внутри локальный CLI. Оркестратор про CLI не знает и знать не обязан: он читает
визитку по известному адресу и ставит задачу. Появится второй рантайм — встанет рядом таким же
агентом, и оркестратор менять не придётся.

🎯 Смысл границы: **зоопарк заперт здесь**. [`neurobox/`](../neurobox/README.md) остаётся тонким и
одинаковым у всех, «поставить ещё один сервер» это правка одной папки, и упавший сервер не роняет
сессии. Это единственное место в репозитории, которое человек пересобирает под себя.

<h2 id="анатомия">🧩 Анатомия</h2>

| Часть                | Назначение                                                     |
| -------------------- | --------------------------------------------------------------- |
| `Dockerfile`         | окружение: node, git, Claude Code; дальше браузер, кому нужен    |
| `agent/src/index`    | A2A-сервер: визитка и приём задач                               |
| `agent/src/executor` | задача протокола → запуск CLI и обратно                         |
| `agent/src/claude`   | соответствие «контекст → процесс» и перевод итога в ответ        |
| `agent/src/session`  | долгоживущий процесс CLI на сессию; вся жизнь процесса здесь     |
| `skin/Dockerfile`    | соседи: MCP и витрина зоны скинов, из чужого репозитория         |
| `skin/web.nginx.conf`| раздача витрины; `/api` и `/presets` — соседям с того же источника |

Визитка агента — `http://127.0.0.1:9100/.well-known/agent-card.json`. Наружу порт опубликован
только чтобы посмотреть глазами и проверить инспектором: оркестратор ходит по внутренней сети
докера, ему публикация не нужна.

<h3 id="вход">🔑 Вход в Claude Code</h3>

Авторизация лежит на именованном томе, а не внутри образа: иначе логин пропадал бы при каждой
пересборке. Каталог создаётся в образе с нужным владельцем ЗАРАНЕЕ — свежий том докер заполняет
содержимым и владельцем того, что лежало в образе на этом месте, а без каталога том достаётся
`root`, и CLI под пользователем `node` в него не пишет.

Вход — один раз, руками, с терминалом:

```bash
docker compose run --rm -it claude claude auth login --claudeai
```

Ссылку из терминала открываешь в браузере на хосте. Проверить потом:

```bash
docker compose run --rm claude claude auth status
```

⚠️ **Конфиг лежал бы ВНЕ тома.** CLI по умолчанию держит `.claude.json` в домашнем каталоге, на
уровень выше `~/.claude` — то есть вне тома, и файл исчезал бы вместе с контейнером на каждом
запуске. Переменная `CLAUDE_CONFIG_DIR` в `compose.yaml` уводит конфиг внутрь тома, к учётным
данным. Без неё вход работает, но CLI на каждом запуске ругается на пропавший конфиг.

<h3 id="развёртка-в-cli">🧩 Как сюда ложится развёртка</h3>

CLI принимает ровно то, что развёртка отдаёт: `--system-prompt` для инструкции и `--mcp-config`
для серверов. Плюс `--strict-mcp-config` — агент видит ТОЛЬКО серверы рецепта и ничего сверх, что
и делает рецепт настоящей границей, а не пожеланием.

🫀 **Процесс живёт сессию, а не сообщение.** Задачи приходят в него потоком
(`--input-format stream-json`), поэтому соединения с MCP не рвутся между ходами и сервер,
держащий состояние (вкладку браузера, например), на следующем сообщении отдаёт его же, а не
пустоту. Развёртка задаётся при старте процесса, так что её смена — это смена процесса: новый
поднимается с `--resume`, беседа продолжается. Простой без работы процесс гасится
(`AGENT_SESSION_IDLE_MS`, по умолчанию 30 минут) — беседа и это переживает, теряется только
состояние серверов.

<h2 id="использование">🚀 Использование</h2>

Серверы объявляются там же, где все остальные — в [`config/`](../config/README.md), обычной
`stdio`-записью с командой и аргументами. Сайдкар читает те же записи; для рантайма разницы между
таким сервером и внешним http-адресом нет.

➕ **Добавить сервер или инструмент** — дописать запись в конфиг и, если он тянет новое
окружение, дописать `Dockerfile` здесь. Всё внешнее и необязательное селится сюда: зона для
этого и заведена.

🚪 **Запасной выход.** Кому этой границы мало — собирает свой образ поверх базового. Это осознанный
выход, а не обход канона: он берёт на себя и вес образа, и его пересборку.

<h3 id="соседи">🏘️ Соседи: зона скинов</h3>

Три контейнера в `compose.yaml` рядом с агентом, все из репозитория
[omnifield/probe-web](https://github.com/omnifield/probe-web):

| Сосед      | Откуда                                          | Порт на петле | Снаружи (через вход) |
| ---------- | ----------------------------------------------- | ------------- | -------------------- |
| `skin-mcp` | `apps/skin/.mcp`, `skin/Dockerfile --target mcp` | 8788          | нет                  |
| `skin-web` | `apps/skin`, `skin/Dockerfile --target web`      | 5174          | `https://<машина>/`  |
| `presets`  | `backend/presets`, Dockerfile их собственный     | 8787          | `/presets/` за витриной |

`skin-mcp` пишет в `presets`, витрина из неё читает — по внутренней сети докера; данные пресетов
на томе `presets-data`. Агент находит MCP по `SKIN_MCP_URL` из `.env` (см. `config/mcp.json`).
Витрина отдаётся своим nginx, и он же проводит `/api` в сервис бокса (чат витрины) и `/presets`
в службу пресетов: адреса в бандле относительные, одна сборка годится везде. Токен чата
впечатывается в бандл при сборке из `ACCESS_TOKEN` — сменился токен, пересобрать `skin-web`.

🔁 **Обновить до свежей ветки** — `ship.ps1` из корня (или `ship.sh` на машине), либо руками:
`docker compose build skin-mcp skin-web presets` и `docker compose up -d`. Образ сам замечает,
что вершина ветки сдвинулась, и не отдаёт кеш; исходники по месту не правятся никогда — их
здесь и нет.

🖥️ **Браузерные ручки MCP (`browser_*`) пусты:** Chrome в образ не ставится. Дока компонентов в
витрине (`VITE_DOCS_URL`) смотрит на `localhost:7777` — на машине этого нет, окно доки пустое.

<h2 id="ио">🔌 ИО</h2>

📥 На входе — объявления `stdio`-серверов из конфига.
📤 На выходе — те же серверы по http, неотличимые для рантайма от внешних.

🚦 Сервер, который не поднялся, отдаётся именованным отказом наверх — молчаливого пропуска нет.
