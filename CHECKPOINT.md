## 🎯 Где мы

Сервис работает на боевой машине целиком: сессия → развёртка → A2A → Claude Code → MCP → ответ,
с записью расхода. Вход в Claude Code сделан, подписка Max. Дальше — привести на ту же машину
продукты из `probe-web`, чтобы агенту было с чем работать.

## ✅ Что проверено живым прогоном

- Вход по токену: без токена 401, кукой 401, с заголовком 200.
- Сертификат настоящий, цепочка проходит без поблажек. Продление без простоя, момент выбирает сам
  центр (проверено: «обновлять через 3 дня 7 часов»).
- Агент отвечает, видит ТОЛЬКО ручки рецепта, расход пишется (токены, кэш, стоимость, мс).
- Собственная ручка бокса — `note_feedback`, знаки `friction` / `praise`.
- Процесс CLI живёт сессию: один процесс, два хода потоком, второй помнит первый,
  идентификатор беседы стабилен (дымовой прогон 2026-09-08).

## 🚧 Следующий шаг

**Человек показывает свой MCP локально** — смотрим его вместе, и если всё в порядке, человек
говорит, что именно поднимать на боевой машине из веба. Разворачивать до этого разговора ничего
не нужно. Целевая зона та же: продукты из `omnifield/probe-web`, ветка `ui-kit` — windshift,
skin MCP, редактор скинов; в репозитории должны быть инструкции и команды — сначала прочитать
их, потом действовать.

Что уже известно про эту зону:

- Витрина `apps/skin` слушает `127.0.0.1:5174` — без неё браузерные ручки MCP бессмысленны,
  поднимать вместе с сервером.
- Skin MCP зовётся `web-core-skin`, 13 ручек, вес описания ~11k символов (~3.6k токенов).
  Один вызов `list_components` — 17 358 символов, тяжелее всего описания в полтора раза.
- Пока skin живёт на ноутбуке (`127.0.0.1:3000`), агент с сервера до него не дотягивается: в
  пульте он честно помечен отказом.
