<h2 id="за-минуту">🏁 За минуту</h2>

Бокс — **менеджер рантаймов**, а не чат и не агентский фреймворк. Он запускает то, что умеет
думать (готового агента вроде Claude Code, локальную модель, чужую по ключу), подключает ему
MCP-зоны по рецепту, считает расход и отдаёт ход работы потоком.

Общение — по открытому протоколу **AG-UI**. Свой формат у бокса был и выброшен: клиент, умеющий
AG-UI, работает с ним без переходника.

Один запрос — один прогон. Разговор бокс не хранит: он твой.

<h2 id="доступ">🔑 Доступ</h2>

Два заголовка на каждый запрос, оба обязательны:

```
Authorization: Bearer <общий токен>
X-User-Login: <логин человека>
```

**Токен** отвечает «можно ли сюда вообще». Он один на приложение, не на человека.

**Логин** отвечает «чьим именем». Из него берётся владелец потоков, и он же уезжает в MCP-зоны
заголовком — зона по нему определяет автора записей. Проверить логин боксу нечем: кто назвался,
тот и владелец. Значит **подставляй его на сервере, никогда не из браузера**, иначе любой
пользователь назовётся чужим именем.

Только латиница и знаки: значение едет в заголовке HTTP, кириллица туда не проходит.

Без токена — `401`. С токеном, но без логина — тоже `401`.

<h2 id="прогон">💬 Прогон: один запрос</h2>

```
POST /api/agent
```

Тело — конверт `RunAgentInput` протокола:

```json
{
  "threadId": "сеанс-работы-42",
  "runId": "прогон-7",
  "messages": [{ "id": "m1", "role": "user", "content": "сделай кнопку пошире" }],
  "tools": [],
  "context": [{ "description": "component", "value": "button" }],
  "forwardedProps": {
    "recipe": "сборка-скинов",
    "passport": "опус-5",
    "agent": "claude-code"
  }
}
```

| Поле | Что это |
| --- | --- |
| `threadId` | сеанс работы. Имя придумываешь ты |
| `runId` | этот ход. Имя тоже твоё; по нему приходят события |
| `messages` | беседа. Берётся **последняя реплика с ролью `user`** — почему, в разделе про память |
| `context` | что приложение знает о месте: страница, компонент, выбранный вариант |
| `forwardedProps` | чем думать и с чем работать. Не указал — возьмутся умолчания |
| `tools`, `state` | принимаются и пока не используются |

Незнакомое поле бокс молча пропускает: протокол растёт, и падать от каждого обновления клиента —
хрупкость на ровном месте.

**Контекст едет отдельно от реплики намеренно.** Склей его с текстом — и агент начнёт на него
отвечать: «да, вижу, вы на странице кнопки». Здесь же он приезжает помеченным как данные.

<h2 id="ответ">📡 Ответ: поток событий</h2>

`text/event-stream`, кадры вида `data: {…}`. **Тип лежит внутри JSON**, в поле `type`, а не в
имени SSE-события: клиент разбирает один поток однородных объектов.

| Событие | Когда |
| --- | --- |
| `RUN_STARTED` | первым кадром, сразу |
| `TEXT_MESSAGE_CHUNK` | агент сказал что-то по ходу дела |
| `TOOL_CALL_START` | зовёт ручку: `toolCallId`, `toolCallName` |
| `TOOL_CALL_ARGS` | аргументы вызова строкой JSON в `delta` |
| `TOOL_CALL_END` | просьба сформирована |
| `TOOL_CALL_RESULT` | **что ручка ответила** — `toolCallId`, `content` |
| `TEXT_MESSAGE_START` / `CONTENT` / `END` | итоговый ответ |
| `RUN_FINISHED` | конец, `result` — тот же ответ |
| `RUN_ERROR` | не получилось: `code` — имя отказа, `message` — словами |

Живой пример, как он приходит на самом деле:

```
RUN_STARTED
TOOL_CALL_START      mcp__skin__list_components
TOOL_CALL_ARGS       {"group": "actions", "limit": 100}
TOOL_CALL_END
TOOL_CALL_RESULT     {"items":[{"component":"button", …
TEXT_MESSAGE_START
TEXT_MESSAGE_CONTENT В группе actions один компонент: button
TEXT_MESSAGE_END
RUN_FINISHED
```

**`TOOL_CALL_RESULT` — то, ради чего стоит слушать поток, а не ждать итога.** По имени ручки и
аргументам видно, что тронуто; по результату — прошло или отказало. На этом строится «агент
сохранил данные — перезапроси их и переключи показ», причём **до** конца прогона.

`toolCallId` у результата — тот же, что у вызова. В одном ходу вызовов бывает несколько, и без
него результат не приписать к своей просьбе.

⚠️ **Встроенные ручки рантайма попадают в поток наравне** с ручками зон: у них в имени нет
приставки `mcp__`. Скрывать то, чем агент реально пользовался, было бы обманом, — но и считать их
своими не надо.

⚠️ **Оборвалась связь — события потеряны.** Переподключиться к идущему прогону пока нельзя, это
в планах. Итог при этом не пропадает: он лежит в слоте потока (см. ниже) до следующего хода.

<h2 id="поток">🧵 Поток и прогон</h2>

Имена придумываешь ты. Бокс своих не выдаёт: двух имён на одну вещь не бывает, иначе тебе
пришлось бы держать таблицу соответствий.

**Поток принадлежит логину.** Пришёл с тем же именем под другим логином — `409`, а не чужой
разговор. Имена придумывают люди, и совпадение — вопрос времени.

Что поток даёт:

- **живой процесс** — пока он не простаивал, агент отвечает сразу, без холодного старта;
- **состояние MCP-зон** — вкладка браузера зоны и подобное живёт, пока живёт поток;
- **группировку расхода** — сколько потратил этот поток.

Правило: **поток на сеанс работы.** Не на сообщение и не навсегда. Человек сел делать кнопку —
один поток на всё, что он с ней делает.

Имя бери случайное. Имя компонента или задачи в роли идентификатора однажды совпадёт у двоих.

Процесс гаснет после простоя (по умолчанию полчаса). Поток после этого работает — просто холодно
и без состояния зон.

<h2 id="память">🧠 Кто помнит разговор</h2>

Модель не помнит ничего — ни локальная, ни чужая по ключу. Помнит **рантайм**: программа, которая
хранит беседу и отправляет её целиком на каждый ход. Помнить должен **кто-то один**, иначе в
контексте окажутся две копии разговора и счёт удвоится.

Сейчас бокс работает с **готовым агентом**: он помнит сам. Поэтому:

- из `messages` берётся **последняя реплика человека**, остальное не отправляется;
- **переписать прошлое нельзя** — сжал вчерашнюю реплику, а агент помнит, как было;
- санитарить реплику перед отправкой **можно и нужно**: человек видит своё, агент получает твоё.
  Это работает, потому что каждое сообщение уезжает отдельно.

Паспорт с сырой моделью, где беседа приходит целиком и переписывать прошлое можно, — в планах.
Выбор «кто помнит» будет свойством паспорта, а не бокса.

<h2 id="отмена">🛑 Отмена</h2>

```
POST /api/agent/{threadId}/cancel
```

Прерывает то, что идёт в потоке прямо сейчас. Отдельным запросом, а не полем конверта:
останавливают уже начатое. Отвечает `{"stopped": true|false}` — было ли что прерывать.

Отменённый прогон закрывается `RUN_ERROR` с кодом `canceled`. Ответа в слоте не остаётся —
человек не должен читать итог работы, которую сам остановил.

⚠️ **Известная поломка: после отмены поток может перестать отвечать.** Следующее сообщение в него
висит до таймаута и падает с `agent-silent`. Пока не починено — заводи новый поток.

<h2 id="расход">💰 Расход</h2>

```
GET /api/agent/{threadId}/spent
```

```json
{
  "thread": "сеанс-работы-42",
  "runs": 7,
  "prompt_tokens": 96,
  "completion_tokens": 21397,
  "cache_read_tokens": 1152848,
  "cost_micros": 2900000
}
```

Деньги в миллионных долях доллара: дробные типы копят ошибку.

Цена хода считается как разница с уже записанным по потоку — рантайм называет накопительный итог
беседы, и сложение таких чисел однажды соврало почти втрое.

Считай в **токенах**: чтение кэша растёт быстрее всего, и по нему видно, что длина разговора —
постоянный налог, а не разовая плата.

<h2 id="отзывы">📮 Отзывы о боксе</h2>

Единственное, что бокс хранит по существу.

```
POST /api/feedback/{threadId}
{ "kind": "friction", "what": "рецепт не дал нужной ручки", "where": "…", "workaround": "…" }

GET /api/feedback
```

`kind` — `friction` или `praise`. **Хорошее записывай наравне с плохим:** по одним жалобам не
видно, что работает, а при переделке важнее знать, чего не трогать.

Агент пишет сюда сам, когда упирается в бокс. От тебя — то, что сказал человек.

⚠️ **Про чужие зоны сюда не пишут.** У каждой зоны свои ручки отзывов, и затык с их ручками нужен
там, где живёт сама зона. У нас он станет записью о том, чего мы не чиним.

<h2 id="каталог">📚 Что можно спросить</h2>

| Ручка | Что отдаёт |
| --- | --- |
| `GET /api/catalog/recipes` | рецепты: с чем агент будет работать |
| `GET /api/catalog/passports` | паспорта: чем он будет думать |
| `GET /api/agents` | рантаймы и их визитки |
| `GET /api/catalog/seeds` | семена — из чего собраны рецепты |
| `GET /api/catalog/refusals` | все имена отказов с объяснениями |
| `GET /api/mcp/servers` | что зоны дают: перечень ручек и их вес |
| `GET /api/health` | жив ли бокс. Без токена |

Имена для `forwardedProps` бери отсюда, а не вписывай на память: на незнакомое имя бокс отвечает
`400` со словами, какое именно не нашлось.

<h2 id="отказы">🚦 Отказы</h2>

Отказы **именованные**. «Что-то пошло не так» нельзя ни показать человеку, ни обработать клиенту.

| Код | Что случилось |
| --- | --- |
| `server-silent` | MCP-зона не ответила |
| `not-probed` | зону ещё не опрашивали, неизвестно, что она даёт |
| `env-missing` | зоне нужна переменная окружения, её нет |
| `transport-unsupported` | так зону подключить нельзя |
| `agent-silent` | рантайм не ответил |
| `agent-refused` | рантайм отказался работать |
| `agent-unknown` | такого рантайма нет в каталоге |
| `run-failed` | прогон закончился отказом |
| `canceled` | остановлено человеком |
| `interrupted` | оборвано рестартом сервиса |
| `seed-unknown`, `name-taken`, `unreadable` | беды слоя настроек |

Коды HTTP на входе: `401` — не пустили (нет токена или нет логина), `400` — незнакомое имя в
конверте, `409` — поток принадлежит другому, `422` — в конверте нет реплики человека или логин
длиннее 64 знаков, `404` — нет такого потока.

<h2 id="чего-не-делает">🚫 Чего бокс не делает</h2>

**Не хранит разговор.** Ни реплик, ни прошлых прогонов с текстом. Остаётся пара «последний вход /
последний выход» на поток, которая перезаписывается каждым ходом, — она спасает результат от
оборванного соединения и не превращается в журнал. История — твоя.

**Не описывает инструменты.** Ручки объявляют владельцы зон. Бокс только подключает их по рецепту
и не знает, что они значат.

**Не толкует, что изменилось.** Он отдаёт факты: какую ручку позвали, с чем, что она ответила.
Решать, что теперь перезапросить, — твоя работа: словарь ручек принадлежит их владельцу, и
зашитый у нас список разошёлся бы с ним на первом же обновлении.

**Не показывает.** Своего лица у бокса сейчас нет: пульт отключён вместе со старым входом.
